## Problem and implementation

The earlier shared Rust answer-support scorer offered deterministic claim-level and citation-level judgments over **human-reviewed** generated answers, but required writing custom Rust to produce a report. A new example executable `crates/wiki-search/examples/answer_support_runner.rs` provides a bounded, no-clobber JSON report and explicit pass/fail thresholds.

Run from the repository root:

```sh
cargo run -p wiki-search --example answer_support_runner --locked -- \
  --suite reviewed_answers.json \
  --output reviewed_answers_report.json \
  --min-claim-support-per-mille 800 \
  --min-citation-precision-per-mille 800
```

The CLI requires `--suite` and `--output`, accepts each optional threshold only once, and validates both thresholds in 0..=1000. A passing gate requires every **supplied** claim and citation to have a reviewer verdict, nonempty reviewed denominators, and scores meeting both integer thresholds. The report records support and precision numerators and denominators without floating-point rounding. Unreviewed judgments are never silently counted as support, and a zero denominator does not pass even when a threshold is zero.

The runner loads at most 2 MiB of UTF-8 input using a single file handle and a bounded read, then invokes `wiki_search::answer_support::evaluate_answer_support_json`. It refuses existing report paths and symlink destinations, checks canonical path aliases against the input, and uses a synced temporary file followed by an atomic no-overwrite hard link. Failed *quality gates* still publish the diagnostic report before returning exit code 1; invalid arguments, invalid label suites and unsafe file paths fail without publishing a report (exit code 2). A successful gate exits 0.

The scorer now recognizes the actual colon-separated revision-block IDs generated by `wiki_model::ArticleKey::block_id`, for example `wkb:enwiki:42:100:b0`. The prior scorer accepted only simplified fixture IDs; this correction is covered by a regression and does not broaden article provenance authority. Both caller-supplied labels and literal model output remain untrusted data.

## Remaining qualifications

This scores **reviewer-labeled** support, not automatic entailment. A reviewer could omit claims, mislabel support, or supply a fabricated article/evidence ID. The current source validates marker consistency against the supplied generated answer, not the actual canonical article content. A genuinely qualified dataset must independently establish source-generation identity, exact article-revision bytes, block membership, reviewer process, question categories and reproducible expected answers.

Next: independently label a representative set of Wikimedia questions and revisions, tie the labels to canonical source snapshots and evidence, produce baseline claim-support/citation-precision reports at exact commits, assess agreement across reviewers, and run the same workload on real desktop/Android environments. The desktop UI still needs the canonical-evidence-to-consent-to-inference-to-validated-citations vertical integration. RAG-003 remains unchecked.
