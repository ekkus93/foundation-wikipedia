# Offline FTS5 article search (STORE-004 partial)

**Status:** Verified deterministic fixture index only. Not yet wired to a fully authenticated installed snapshot, pack builder, Android reader, or release acceptance.

## Implemented boundary

`wiki_store::search_index::OfflineSearchIndex` stores a **derived** SQLite FTS5 index with the canonical article's project/page ID, exact revision ID, title and text from validated structured blocks. Section headings, paragraphs, lists, tables, infobox labels/values, mathematical source text and footnotes are indexed. Canonical display titles and Unicode title aliases are searchable as well, while each hit still carries one exact page/revision identity. Raw HTML fallbacks and binary media are deliberately excluded rather than being interpreted as trusted plain text.

`rebuild(&[Article])` replaces the index in one SQLite transaction. `rebuild_streaming` accepts fallible article-by-article sources, while `rebuild_from_catalog` visits digest/identity-verified compressed frames individually without materializing the entire corpus. For a catalog rebuild, a second bounded streaming pass follows each verified redirect chain and appends its title to the *canonical article's* FTS text; no duplicate redirect result is created. Cyclic, dangling or corrupt redirects and text-budget violations roll back the transaction, retaining the previous complete search index. A corrupt late article frame also rolls back. Invalid articles, duplicate page identities, oversized text and SQLite failures roll back the transaction; an older complete index remains queryable. An empty input deliberately clears the index. A persisted SQLite database can be reopened and rebuilt without downloading source data again. Queries are bounded to 8192 UTF-8 bytes and 32 Unicode alphanumeric tokens, quoted before binding to FTS5 MATCH; ranking uses BM25 with title boost and stable project/page-ID ties, capped at 100 results. No search path initiates network requests.

## Tests

`cargo test -p wiki-store --test offline_search --locked` checks title-vs-body ranking, Unicode matching, query limits/operator treatment, duplicate-identity rollback, exact-revision replacement, persistence and full rebuild. Workspace CI also runs formatting, strict Clippy and Rust tests. These are synthetic canonical article fixtures, not a representative offline topic pack.

## Remaining acceptance

This is **not STORE-004 completion**. Required: authenticate and completely verify the input immutable snapshot/catalog (the incremental streaming reader does not confer provenance), add pack installation/activation ownership and corruption recovery; benchmark large multilingual article sets and disk/Android RAM; integrate actual desktop/Android offline search and source-version labeling; and qualify airplane-mode behavior. Index contents must never confer publisher trust or offline-ready status. All required visual media and attribution remain a separate pack-completeness gate.

## Verified redirect alias search (2026-10-11; STORE-004 partial)

`OfflineSearchIndex::rebuild_from_catalog` makes two bounded passes over per-frame-verified catalog records, using one SQLite transaction. Articles are indexed first. Each subsequent redirect title resolves through `SnapshotCatalog::resolve_title` (including multi-hop chains), then enriches the already indexed *canonical* article FTS row. Search hits retain canonical project/page ID and exact revision; `resolve_hit` rechecks the addressed catalog record. No redirect becomes a separate searchable result, so duplicates are not introduced. Text and redirect-count ceilings are fail-closed, and a missing target, cycle, corrupt source, over-budget body or transaction failure preserves the previous derived index. This does not prove snapshot authenticity, official pack trust, visual completeness or an offline device experience.

## Atomic persisted-index recovery (2026-10-11; STORE-004 partial)

`OfflineSearchIndex::replace_persisted_from_catalog` rebuilds a *new* derived FTS5 SQLite file from verified catalog frames even when the existing search DB cannot be opened. It refuses symlinked/unsafe immediate parent and output paths, uses bounded create-new temporary path allocation, validates and fsyncs the completed database, and atomically replaces the destination only after all catalog records and redirects pass. A corrupt source frame, missing redirect target, SQLite error or other pre-publication failure leaves the old index untouched; failed temporary files are removed. This API assumes exclusive access to the search directory and no active reader/SQLite connection to the old database. It does not authenticate the upstream snapshot or imply publisher trust.

- **Code:** `af9e6220f6cb1d47210a98d0a12f2b1dbf8a44ec` passed [Rust workspace CI 38162290509](https://github.com/ekkus93/foundation-wikipedia/actions/runs/38162290509), [Platform shells CI 38162290578](https://github.com/ekkus93/foundation-wikipedia/actions/runs/38162290578), and [Android ABI CI 38162290462](https://github.com/ekkus93/foundation-wikipedia/actions/runs/38162290462). This is not full-snapshot integrity, crash/power-loss, disk-full or real-device acceptance.

### Private permissions on atomic FTS recovery (2026-10-11; STORE-004 partial)

The recovery writer now creates its private staged SQLite file with Unix mode `0600`, rather than relying on a process umask that commonly yields world-readable `0644`. The staged file is renamed to the published index only after successful rebuild. A Unix regression asserts that the published index remains owner-only after corrupt-index recovery; source shards and media are not modified. Code SHA `2448b114ee4108e1c4dd6044a75a93200215a53f` passed [Rust CI 38164558624](https://github.com/ekkus93/foundation-wikipedia/actions/runs/38164558624), [Platform CI 38164558700](https://github.com/ekkus93/foundation-wikipedia/actions/runs/38164558700) and [Android ABI CI 38164558737](https://github.com/ekkus93/foundation-wikipedia/actions/runs/38164558737). This covers only the recovery-created SQLite file on Unix; existing databases created through other APIs, ancestor-directory access controls, concurrent filesystem attackers, full-snapshot authenticity and offline-device acceptance remain outside this fixture. **STORE-004 stays unchecked.**

### Existing-index filesystem constraints (2026-10-11; STORE-004 partial)

Before opening an existing derived SQLite index or replacing one from catalog frames, the shared path guard rejects symbolic links at **any ancestor** (not only the immediate parent) and rejects non-regular destination files. On Unix an existing index must have just one hard link and no group/other permission bits. A missing index is created owner-only (0600) through a create-new operation. These checks assume an exclusively controlled private directory: pathname validation and SQLite opening are not a race-free defense against a concurrent attacker capable of renaming files or directories. Existing permissive indexes must be removed/recreated under a private path instead of being opened through this API.

- **Code and fixtures:** `2d19200359986d99f65504192c88dfabf1b1ab38`. The Unix regression exercises a world-readable index, a multiply-linked index, and a symlinked grandparent; all fail before SQLite can touch the target. The corrupt-index recovery fixture now uses owner-only initial file permissions.

### Catalog-wide shard completeness guard (2026-10-11; STORE-004 partial)

The new `OfflineSearchIndex::replace_persisted_from_verified_shards` checks an independently obtained expected mapping of shard paths to sizes and SHA-256 digests through `SnapshotCatalog::verify_manifest_shard_hashes` before building and atomically publishing a derived FTS5 index. A valid digest for the *indexed* frame alone is insufficient: trailing unindexed records fail the coverage check, as does a mismatched expected shard hash. Failure preserves the last-good search index, and complete digest-consistent fixtures rebuild with both page IDs searchable. This API does **not** establish authority of the supplied expected manifest, prove source generation completeness, or confer official pack trust.
