# STORE-002: Unregistered published-media orphan audit (2026-10-26)

**Status:** Scoped read-only GC preflight; STORE-002 remains unchecked.

The existing `plan_unowned_media_gc` inspects registered objects with zero owners. It cannot detect content-addressed bytes published to disk before a crash interrupts the corresponding SQLite registration. The new `media_gc::plan_unregistered_media_gc` complements that view: it enumerates bounded, canonical digest paths in the media store, excludes already registered digests regardless of pack/cache/pin ownership, and rehashes each unregistered object through the existing streaming SHA-256 verifier before reporting a deterministic candidate list and total bytes.

The path walk rejects malformed names, unexpected directories, symlinked prefix directories and nonregular published paths, and refuses more than 10,000 scanned published objects. It ignores only well-formed `.PID.COUNTER.tmp` staging filenames, which are not fully published media and remain a separate recovery problem. Invalid scan limits, over-limit scans, corrupt bytes and unsafe paths fail without mutation. The registry lookup checks row existence and registered size but does not confer publisher provenance.

**Important safety boundary:** This API is an advisory snapshot only. A writer can register an object after the lookup; a reader can hold a lease, and an interrupted publication may leave a staging file. No deletion or registry mutation occurs. Production GC still needs a writer/reader coordination protocol, durable crash recovery, and revalidation at the moment of any unlink. This is not proof of source authenticity, complete offline media, or device acceptance.
